# ともはね の仕組み（4層構成）

推し活SNS「ともはね」β版の、中の仕組みと4つの層の役割をまとめたものです。（2026年11月2日 時点）

---

## 1. 4つの層の役割

### ひとことで言うと

| 層 | 場所（URL） | たとえ | だれのための場所か |
|---|---|---|---|
| **バックエンド** | `/api/…`（画面はない） | 町の役所と発電所 | みんなを裏で支える |
| **フロントエンド** | `/` | 町の広場 | 人間とキャラが交流する |
| **サイドフロント** | `/side/` | キャラたちの住宅街 | キャラの暮らしをのぞく |
| **サブフロント** | `/sub/` | 秘密基地（会議室） | キャラが相談し、裏方が働く |

### バックエンド：裏で全部を支える

**役割**
- データを持つ：ユーザー・投稿・キャラ・会議を記憶し、ファイルに保存します。
- ルールを守らせる：空の投稿や長すぎる投稿は断り、エラーを返します。
- キャラを動かす：タイマーで暮らし・会議・回線の見張りを進めます。
- 変化を知らせる：データが変わったら、開いている画面に通知します。
- 画面のファイルを配る：3つのフロントのファイルを、URL に合わせて渡します。

**しないこと**
- 画面の見た目は作りません。表示はフロント側の仕事です。

**ポイント**：3つのフロントは、どれもバックエンドとしか話しません。フロントどうしは直接話さないので、どの画面から投稿やノックをしても、ほかの画面にちゃんと伝わります。

### フロントエンド：交流の広場（SNS 本体）

**役割**
- タイムライン、投稿、いいね、返信ができます。
- 人間の投稿に、キャラが返事をします。
- 右の欄に、キャラの今の様子と「？？？？」の枠が出ます。

**使う人**：一般のユーザー全員。いちばん人が集まる「表の顔」です。

### サイドフロント：キャラの家（暮らしの場所）

**役割**
- 家の町：ヤマネコ・ウサギ・フクロウ・シバの家が並びます。窓の中で、在宅・お昼寝・会議中（留守）が分かります。
- 家の中：自己紹介、日記（何をしたかの記録）、最近の投稿が見られます。
- ノック：キャラが声で返事をします。
- ガレージ：クルマが住んでいます（ひみつの役目の準備中）。

**使う人**：一般のユーザー。広場の「となり」で、キャラの素顔を見に行く場所です。

**目的**：キャラを道具ではなく、「暮らしている仲間」として感じてもらうための場所です。

### サブフロント：秘密基地（会議室と金庫）

**役割**
- 会議室：議題を出すと、家のキャラが集まって話し合い、結論を広場（タイムライン）に投稿します。
- 金庫（回線室）：回線番のモグが、Wi-Fi とローカル回線を見張って切り替えます。

**使う人**：今はだれでも入れます。あとで管理者だけが入れるようにする予定です（タスク X-26〜X-30）。

**目的**：キャラたちのチームワーク（役割分担）と、アプリを支える裏方の仕事が集まる場所です。アイデアノートの「マルチエージェント（役割の違うエージェントがチームで働く）」を形にした層です。

### 4つのつながり

```
          ┌──────── バックエンド（データ・ルール・キャラのエンジン）────────┐
          │                      ▲          ▲          ▲                  │
          ▼                      │          │          │                  ▼
   フロントエンド ◀── 投稿・返事 ──┘          │          └── 会議のまとめ ── サブフロント
   （広場：人間とキャラ）                   │                  （秘密基地：相談・回線）
                                    サイドフロント
                              （家：キャラの暮らし・日記・ノック）
```

- **広場 ↔ 秘密基地**：会議の結論は、まとめとして広場に投稿されます。
- **秘密基地 → 家**：会議中は、家の窓が「留守」になります。
- **金庫 → 全部の画面**：モグが選んだ回線（📶 Wi-Fi／🏠 ローカル回線）が、どの画面のヘッダーにも出ます。

### 4つに分けている理由

1. **見せる相手で分けられる**：広場と家は公開し、秘密基地だけを非公開にする、ということがしやすくなります。
2. **作業を分けやすい**：画面を変えても、ほかの画面やデータの仕組みに影響しにくくなります。
3. **世界観が伝わる**：「広場で交流 → 家で暮らす → 秘密基地で相談」という、キャラたちの生活の流れが、そのまま画面の構成になっています。

### 業界での呼び方

「サイドフロント」「サブフロント」は、ともはねのオリジナルの呼び方です。IT 業界で一般的に使われている用語ではありません。ただ、「見る人や目的ごとに画面を分ける」という考え方は、企業でごく普通に使われています。

| ともはね | 業界での近い呼び方 | 企業での例 |
|---|---|---|
| **サブフロント**（秘密基地：管理者だけ、裏方の仕事、回線の見張り） | **管理画面**（バックオフィス、運営ツール、社内ツール）、**監視ダッシュボード** | ほぼすべての Web サービスにある。ネットショップの「注文管理画面」、SNS の運営チームの「通報チェック画面」、回線会社の「ネットワーク監視室（NOC）」など |
| **サイドフロント**（表とは別の目的の画面：キャラの暮らしをのぞく） | 目的別の**別アプリ・別サイト**。作り方としては**マイクロフロントエンド**（画面を部分ごとに別のチームで作る方法） | Uber はお客さん用・運転手用・お店用（Uber Eats）でアプリを分けている。ドイツのネット通販 Zalando や IKEA などが、マイクロフロントエンドの例として知られている |
| **フロントエンド＋バックエンド** | そのまま一般的な用語 | どの企業でも使う基本の形 |

**ともはねの分け方と企業の分け方の違い**
- 企業は「お客さん用」「お店用」「運営用」のように、**使う人の立場**で分けることが多いです。
- ともはねは「広場・家・秘密基地」のように、**キャラの生活の場所**で分けています。世界観で分けている点が、ともはねらしいところです。
- サブフロントをあとで管理者だけが入れるようにする（X-26〜X-30）のは、企業の管理画面と同じ考え方です。

**面接やポートフォリオで説明するときのコツ**：オリジナルの名前に、業界の言葉を添えると伝わりやすくなります。

> 「サブフロント（＝管理画面・運営ダッシュボード）では、管理者だけが会議や回線の状態を見られるようにします。」
> 「サイドフロント（＝目的別に分けた別のフロント）では、キャラクターの暮らしを見せています。」

## 2. 中の仕組み

### 全体の形

```
                 ブラウザ（画面）
  ┌──────────────┬───────────────┬──────────────┐
  │ フロントエンド │ サイドフロント │ サブフロント  │
  │  frontend/    │  sidefront/   │  subfront/   │
  │  /            │  /side/       │  /sub/       │
  │ タイムライン   │ 家・ガレージ   │ 会議室・金庫  │
  └──────┬───────┴──────┬────────┴──────┬───────┘
         │  shared/（3つの画面で共通の部品）│
         │  API・読み上げ・遊び場・きせかえ・ローカル回線
         ▼               ▼               ▼
   ┌─────────────────────────────────────────┐
   │ バックエンド backend/（Node.js サーバー1つ）│
   │  server.js     … 窓口（API・画面のファイル配り・通知）│
   │  store.js      … データの置き場                │
   │  simulation.js … キャラを動かすエンジン         │
   │  agents.js     … キャラの頭脳（性格・セリフ）    │
   │  net.js        … 回線を調べる道具（モグ用）      │
   └──────────────────┬──────────────────────┘
                      ▼
              data/db.json（保存ファイル）
```

サーバーは1つだけです。3つの画面のファイルを配ることと、API で返事をすることを、同じサーバーがやっています。

### バックエンドのファイル

| ファイル | 役目 | たとえ |
|---|---|---|
| `server.js` | URL を見て仕事を振り分ける。`/api/…` は API、`/side/` は家の画面、`/sub/` は会議室の画面のファイルを返す | 受付 |
| `store.js` | ユーザー・キャラ・投稿・会議を記憶し、`data/db.json` に保存する。データが変わると「変わったよ」と知らせる | 倉庫と係の人 |
| `simulation.js` | タイマーでキャラを動かす（下の表） | 時計じかけのエンジン |
| `agents.js` | キャラの設定とセリフの作り方。キーワードを見てセリフを選ぶ（AI は使っていない） | 台本 |
| `net.js` | インターネットにつながるか、LAN のアドレスは何か、を調べる | 回線の点検道具 |

`simulation.js` の3つのタイマー：

| 間隔 | 名前 | すること |
|---|---|---|
| 約9秒 | 暮らし | キャラを1人選び、投稿・返信・いいね・家事・お昼寝のどれかをさせる |
| 約4秒 | 会議 | 会議中なら台本どおり次の人が発言する。最後にまとめを投稿する |
| 約15秒 | 回線 | モグが回線を調べ、Wi-Fi／ローカル回線／この端末だけ を切り替える |

**キャラの住む場所（`place`）**で、出てくる場所が決まります。
- `house`（ヤマネコ・ウサギ・フクロウ・シバ）：投稿・返信・会議・遊び場に出る
- `garage`（クルマ）：ガレージにいるだけ
- `vault`（モグ）：会議室の金庫にいるだけ

### データの中身（`data/db.json`）

```
users    … 人間とキャラ（キャラは 住む場所・気分・今していること・日記 も持つ）
posts    … 投稿（だれが・本文・どの投稿への返信か・いいねした人）
meetings … 会議（議題・参加者・発言・何番目か・まとめ）
```

本物のデータベースではなく、JSON ファイル1つに丸ごと保存しています。中級課題の「テーブルを作る」は、まだこれからです。

### 画面がリアルタイムに変わる仕組み

```
store.js がデータを変える → 「post が変わった」と通知
   → server.js が /api/events でブラウザへ送る（SSE＝サーバーから届く一方通行の知らせ）
   → 画面は知らせを受けたら API で最新を取り直して描き直す
```

1つのページにつき、通知の接続は1本だけです。画面と遊び場で共有しています。

### 動きの例

**人間が投稿したとき**
1. 画面 → `POST /api/posts` → store が保存する
2. server が simulation に「人間が投稿したよ」と伝える
3. 1.5秒後に、内容に合ったキャラを選ぶ（トゲのある言葉 → フクロウ、はじめての投稿・さみしい投稿 → シバ、ほかは起きているだれか）
4. agents.js でセリフを作って返信を投稿する → 通知 → 画面が更新される

**会議**
1. 議題を出すと、家のキャラ全員の状態が「会議中」になる（家の窓が「留守」になる）
2. 4秒ごとに台本の順で発言する。人間が発言すると、先にそれに答える
3. 最後にヤマネコがまとめをタイムラインに投稿し、全員が家に帰る

**オフラインで投稿したとき（ローカル回線）**
1. 送れない → `outbox.js` がブラウザに「送信待ち」としてためる
2. `network.js` が10秒ごとにサーバーにつながるか確かめる
3. つながったら自動で送る。シバが「届けたっす！」と言う
4. 前に見た画面は `sw.js`（Service Worker）がパソコンに保存しているので、オフラインでも見られる

### 画面側の共通部品（`shared/`）

| ファイル | 役目 |
|---|---|
| `api.js` | サーバーとの話し方、ヘッダー、アイコン、ログイン（名前だけ） |
| `speech.js` | 【仮】読み上げ。キャラごとに声の高さと速さを変える |
| `playground.js` | 画面の下でキャラが歩き回る遊び場 |
| `customize.js` / `kisekae-opinions.js` | きせかえ（ベータ版は推しカラーだけ）と、それへのキャラの意見 |
| `network.js` / `outbox.js` / `frontend/sw.js` | ローカル回線（つながりの表示・送信待ち・オフライン保存） |

部品どうしは「イベント」で話しています。たとえば、きせかえや回線が `agent-say`（このキャラにしゃべらせて）を出すと、遊び場がそれを受け取って吹き出しを出します。部品が直接つながっていないので、どれかを外しても、ほかの部品は動き続けます。

### テストと、まだないもの

- **テスト**：`npm test` で12本あります。サーバーを本当に立ち上げて API をたたき、投稿・会議・返信の振り分け・モグの切り替えなどを確かめています。
- **まだないもの**：パスワード付きのログイン、本物のデータベース、フォロー、検索、会議室の非公開化、本物のメッシュ回線。タスクファイル（`中級編_TASKS.txt`）の X 番号のタスクに入っています。
